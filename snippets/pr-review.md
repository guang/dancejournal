## Overview

Rewrites the dancejournal.app landing page from a three-pillar layout (Feedback / Compare / Progress) into a single student-first narrative: Nav · Hero · HOW IT WORKS (a vertical timeline of 6 numbered steps + 1 unnumbered bonus) · Final CTA · Footer. Two follow-up commits swapped static screenshots for autoplaying video loops on steps 1–3 and 6, retuned the phone-frame aspect ratio, replaced the bonus row's interactive notebook demo with a screenshot, tightened all timeline copy, and fixed a nav-overflow bug. PR: [#21](https://github.com/guang/dancejournal/pull/21), issue [#20](https://github.com/guang/dancejournal/issues/20).

## Issues to Address

- [x] ~~**[bug] Bonus demo phone renders squashed on desktop/tablet (>720px)**~~ — Moot: the bonus row no longer uses `.dz-app-phone` at all. — fixed in `4e95308`.

- [x] ~~**[bug] Video recording-pill crop clips real UI off the left/right edges**~~ — `assets/landing.css` (`.dj-phone-screen video`) — `455be78`'s fix for the red iOS recording-pill (visible because `object-position: top` keeps the source's top edge, pill included, fully in frame) oversized the video box to `height: 122%` with `top: -12%` to push the crop point down. Oversizing the box changed *its own aspect ratio* (0.41) away from the container's (0.5), which flipped `object-fit: cover`'s crop axis from vertical to horizontal — confirmed by rendering it: the right-side action rail ("Practice"/"Note"/"More") and left-edge captions were being cut off on all 4 videos, both desktop and mobile widths. _Fix applied:_ reverted to the same `width:100%; height:100%` box as `img` (matches container aspect, so `cover` only ever crops vertically), and simply changed `object-position` from `top center` to `bottom center` for `video` — this spends `cover`'s existing ~7–8% vertical crop budget on hiding the top chrome instead of the bottom, with zero horizontal side effects. Verified via ffmpeg-extracted frames + live browser render (network + screenshots) across all 4 videos at desktop (1024px) and mobile (375px) widths — no more edge clipping. — fixed in `098b842`.
  - **Residual, minor — since resolved:** this crop-budget approach left a sliver of the red pill visible during the "swipe to step" transition segment, and was actually leaving *more* than a sliver visible everywhere once the real content-box math was checked (see the mask-based fix below). Superseded entirely by the opaque per-clip mask; no longer a crop-budget problem since the mask isn't frame/content-dependent.

Confirmed zero remaining references via full-repo grep before deleting. — fixed in `098b842`.

- [x] ~~**[concern] Four autoplaying videos load unconditionally on page load, ~5MB total, no lazy-loading**~~ — `index.html`, `assets/landing.js` — Removed `autoplay` and changed `preload="auto"` → `preload="none"` on all 4 timeline videos; added `initLazyVideos()` (IntersectionObserver, 200px rootMargin) that calls `.play()` once a video is about to scroll into view, then unobserves. Verified via the network tab: page load now fetches only the 4 lightweight poster JPGs (0 `.mp4` requests); scrolling to step 1/2 triggers exactly those two `.mp4` requests, with steps 3/6 still unfetched until scrolled closer. — fixed in `098b842`.

- [x] ~~**[bug] The `098b842` recording-pill fix still left it partly visible (user-reported, with screenshot)**~~ — `assets/landing.css`, `index.html` — Root cause: `.dj-phone-screen`'s actual content box is smaller than the crop math in `098b842`'s comment assumed. `.dj-phone` is `box-sizing: border-box` with `padding: 10px` + `border: 2px`, so on desktop the real content box is 236×496 (ratio 0.4758), not the nominal 260×520 (ratio 0.5) the comment used — `object-fit: cover` at the *real* ratio only had ~29px of top crop budget, not ~78px, leaving roughly the bottom half of the pill (measured at source y=16–45px in all 4 clips, via `ffmpeg` frame extraction across each video's full duration) exposed. Also discovered mid-fix: 2 of the 4 clips (`step-2-goal`, `step-3-loop`) don't have a small pill at all — they have a full-width **black recording toolbar** (`↔ swipe to step` + a red dot icon) covering the top 10.89% of the frame, measured by scanning for full-width-black rows. _Fix:_ replaced the crop-based approach entirely with an opaque `::before` mask on `.dj-phone-screen:has(video)`, height/color set per-clip via inline CSS custom properties (`--rec-mask-h`/`--rec-mask-bg`) sized from the measured chrome extent + margin: 6% white for step-1, 12% black for step-2/3, 6% off-white (`#f7f6f6`) for step-6. Percentage-based, so it's identical at every viewport width — no separate mobile handling needed. Verified by simulating the browser's exact `object-fit: cover` math in Python/PIL against the real content-box dimensions (236×496 desktop, and a scaled-down mobile box at the same ratio) for all 4 posters: no recording chrome visible in any of the 8 renders, no real UI (back chevron, title, header text) clipped. Reverted the now-unnecessary `object-position: bottom` crop override for video back to the shared default (`top center`, same as `img`). — fixed in `8978e78`.

## File Groups

### 1. Landing page markup — `index.html`
Timeline steps 1–3 and 6 now use `<video>` with `preload="none"` (no `autoplay` attribute — playback is now driven entirely by `initLazyVideos()` in `landing.js`, keyed off the new `data-lazy-video` attribute). Copy across all 7 timeline entries was shortened for scannability; em dashes replaced with hyphens throughout (title/OG/Twitter tags too). "(beta)" dropped from the Android line now that it's out of beta. Each of the 4 video steps' `.dj-phone-screen` now carries inline `--rec-mask-h`/`--rec-mask-bg` custom properties sizing that clip's recording-chrome mask (see Styling below) — if a 5th video step is ever added, it needs this pair too, sized from the clip's own measured chrome height.

### 2. Styling — `assets/landing.css`
912 → 504 lines this session. `.dj-phone-screen:has(video)::before` paints an opaque top mask (height/color from the per-instance `--rec-mask-h`/`--rec-mask-bg` custom properties set in `index.html`) to hide each clip's baked-in recording indicator — replacing an earlier crop-based approach that turned out to be short by roughly half the pill's height once `.dj-phone`'s `border-box` padding was accounted for (see Issues to Address for the full root-cause). `video` now shares `img`'s plain `object-fit: cover; object-position: top center` with no special-casing. All CSS for the removed three-pillar sections and the removed notebook-demo engine is gone — the file now contains only rules with a live selector match in `index.html`. Nav gets `flex-wrap`/`row-gap` so the "Get it for + iOS + Android" fallback wraps instead of overflowing on narrow desktop widths (verified: it never actually needs to wrap in practice, see Key Workflows).

### 3. Behavior — `assets/landing.js`
460 → 150 lines. The dead notebook-demo controller (`init()`, scrubber/chat-thread/speed-toggle logic) is gone. New `initLazyVideos()` lazily starts each timeline video via `IntersectionObserver` instead of relying on the `autoplay` attribute, with a synchronous `.play()` fallback for browsers without `IntersectionObserver` support.

### 4. Media — `assets/shots/*`, `assets/video/*`
`notebook-demo.mp4`/`-poster.jpg` (orphaned by this PR) and `library-overview.mp4`/`-poster.jpg` (already orphaned before this PR) are deleted — both fully unreferenced, confirmed via repo-wide grep before removal.

### 5. Social share card — `assets/social/og-card.html`, `assets/social/og-card.png`
Untouched this session.
